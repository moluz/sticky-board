# 便签墙 + 任务板 DSH 插件 · 调研与初步方案

> 版本：v0.1（2026-11-09）  
> 目标：做一个「便签墙 + 任务板」二合一的 DeepSeek Harness Web UI 插件，先摸清已有轮子，再决定怎么造。  
> 结论先行：**市场里便签类、看板类单点能力都已齐全，但「便签墙 + 任务板 + 双向联动 + 模型工具」的组合仍是空白；建议以 MIT 许可的 `dsh-plugin-sticky-wall` 为底座二开，任务板自建、不引入重型白板/看板库。**

### 3.4 关键判断

1. **单点已卷**：便签墙、磁贴墙、无限画布、看板、甘特/日历都有人做了，重复造一个「纯便签」或「纯看板」价值低。
2. **组合仍空白**：没有任何插件把「自由摆放的便签墙」和「带状态/优先级/截止的任务板」放进同一份数据，并支持互相转换。`life-workbench` 只是把两块拼在一个面板里，数据模型没有联动。
3. **模型工具已成标配**：便签类普遍 4–5 个工具，看板类 13–19 个；新插件若不提供工具，会明显落后。
4. **许可证友好**：上面这些同类插件几乎全是 MIT，可放心参考/局部复用（保留版权声明即可）。

## 4. 同类项目的实现路径拆解

### 4.1 通用骨架（所有 bundle 型插件一致）

```
my-plugin/
├── package.json        # dsh.bundle.patch + dsh.client{platform:"web", immediately}
├── cordis.patch.yml    # insert: [{ id, name, config }]
├── index.js            # Host 半：export name / inject / apply(ctx)
├── client.js           # Client 半：window.__ModuleLoader__.load({ id, factory(require){…} })
├── locale/{zh,en}.json # meta.title / meta.description + UI 文案
└── icon.svg
```

安装：`plugin_manager action=install_bundle target=<包绝对路径>`；Host 半改动需重启/关开插件，Client 半改动刷新页面即可。

### 4.2 六个代表项目的「宿主半 × 客户端半」

| 项目 | Host 半 | Client 半（落点） | 通信 | 持久化 | 可复用点 |
|---|---|---|---|---|---|
| `dsh-plugin-sticky-wall` | 37KB 单文件 `index.js`：行模型、存储、HTTP 端点、5 个工具，**零第三方依赖** | 115KB 手写 `client.js`：`sidebar.panellist`（id=`sticky-wall`）+ `main`（同 key）整面墙 | 同源 `fetch` 到 `/api/dsh-sticky-wall/*`；`Sec-Fetch-Site`/`Origin` 校验、POST 仅 JSON | `$DSH_HOME/sticky-wall.json`，原子写、内容不变跳过、revision 并发保护、损坏改名备份 | **首选底座**：墙的拖拽/缩放/折叠/行模型/回收站/工具/持久化全部现成 |
| `@vfvrpq/dsh-sticky-notes` | `storageDomain` + 4 工具 + `/api/dsh-notes` 路由 + `webserver/index-inject` 下发 routePath | 侧栏入口 + 磁贴板 / 编辑弹窗 | 同源 `fetch`；路由挂在 `/api` 下吃宿主鉴权围栏 | **storageDomain**（record 级表 + 版本 + schema 校验） | 想升级到「结构化表格存储」时抄它的 domain/route 写法 |
| `dsh-noteboard` | 工作区文件系统（`.md` + `.canvas`）+ 12 工具 + 5 个工作流 | 会话内无限画布 | Host RPC / 文件读写 | 工作区文件，Git 可管 | 想「内容与布局分离、可 Git」时参考；但复杂度高 |
| `dsh-project-kanban` | 13 个 `kanban_*` 工具 + `/api/kanban` 数据层；工具用 `exec.agent.session.header.cwd` 定位工作区 | 会话头部「看板」tab | 同源 `fetch` | `kanban-board-<workspaceId>.json` | **任务板数据模型与工具设计的最佳参考**（标签/优先级/截止/回收站/撤销/排序） |
| `@alpacachen/dsh-kanban` | 19 工具 + 附件/评论/活动 | 左上「Board」页 + 每工作区一块板 | 本地 | 板文件 + attachment store | 交互与信息密度参考（P0-P2、评论、图片） |
| `dsh-todo-time-log` | 单一 `todo_time_log` 工具 + `/api/dsh-todo-time-log/*`，UI 与工具共用同一业务实现 | 中央 `main` + `sidebar.panellist`，四视图 | 同源 `fetch` | JSON + 原子写 + 跨进程文件锁 + 导入导出/迁移 | **工程化范本**：工具/HTTP/UI 三入口共用实现、版本迁移、备份撤销 |

### 4.3 从中提炼的结论

1. **面板落点**：左栏 `sidebar.panellist` 给入口，中央 `main` 给整页；`main` 的 key 必须与 `sidebar.panellist` 的 `id` 一致，点击后 `ctx.layout.selectPanel(id)`。
2. **Host 是数据权威**：Client 只做 UI，数据经同源 HTTP 回 Host 落盘；这样才能跨端口、跨浏览器、跨重启，而且模型工具能读到同一份数据。
3. **工具与 UI 必须共用同一实现**（`dsh-todo-time-log` 的 `executeTodoAction`、`sticky-wall` 的 repository），否则两边规则会漂移。
4. **写盘策略**：`tmp + rename` 原子替换 + 内容未变跳过 + revision 保护 + 损坏备份，是这些单文件插件的共同做法。
5. **不要用重型白板 SDK**：没人用 tldraw/Excalidraw 做这类插件，都是 React + CSS + 指针事件自绘。

### 5.4 可借鉴的数据模型要点

- 看板扁平三层：**board → list（列）→ card**；card 挂 `labels`、`checklist`、`dueDate`、`rank`（浮点排序，拖拽只改一张卡，避免整列重写）。
- 就地编辑用 `contenteditable` / 输入框 + debounce 提交；离线参考 Super Productivity 的 op log 思路（本插件单机，暂不需要 CRDT）。
- 本项目墙的 `lines[]`（正文/待办/无序/有序）与看板卡的 `checklist` 可以同构，便于「便签 → 任务」转换。

### 5.5 编辑器与状态

- MVP：`textarea + Markdown 轻渲染`（与现有插件一致，零依赖）。
- 进阶：TipTap（MIT）替换，数据仍存纯文本/JSON；BlockNote 为 MPL-2.0，注意修改文件需开源。
- 状态：局部 React state + Host 权威数据即可；**不要**引入 Yjs/Loro 这类 CRDT（单机场景纯负担）。
- 浏览器侧持久化（IndexedDB/Dexie）**不适合本插件**：数据必须落在 Host，才能给模型工具用、跨浏览器/端口稳定。

## 6. DSH 插件机制（已按 0.2.2-rc.1 核验）

### 6.1 清单与安装

- `package.json`：
  - `exports`：`"."`→Host 入口、`"./client"`→Client bundle；
  - `dsh.bundle.patch`：指向 `cordis.patch.yml`；
  - `dsh.client`：`{ "platform": "web", "immediately": true, "inject": [...] }`；
  - 建议声明 `engines.dsh: ">=0.2.1-rc.4 <0.3.0-0"`（与 sticky-wall 一致）。
- `cordis.patch.yml` 只做一件事：`insert` 一行 `{ id: sticky-board, name: "@local/sticky-board" }`。
- 安装用 `plugin_manager action=install_bundle`，返回值 `application: "applied"` + `warnings` 才代表生效。

### 6.2 Client 半（浏览器）

```js
window.__ModuleLoader__.load({
  id: "sticky-board",
  factory(require) {
    const React = require("react");
    const h = React.createElement;
    // …组件…
    return { inject: ["slots", "locale", "layout"], apply(ctx) {
      ctx.effect(() => ctx.slots.inject("main", () =>
        ctx.slots.register({ name: "main", key: "sticky-board", locale: NS }, Panel)));
      ctx.effect(() => ctx.slots.inject("sidebar.panellist", () =>
        ctx.slots.register({ name: "sidebar.panellist", id: "sticky-board", order: 16, label: () => t("view.label"), locale: NS }, Icon)));
    }};
  },
});
```

要点（踩坑清单）：
- `factory` 必须 `return module.exports`（漏掉会报 `invalid plugin … received undefined`）。
- React 由平台种子表提供（`require("react")` / `require("react/jsx-runtime")`），**不要**另装 React、不要 CDN。
- 不要 `import`/`require` 任何 `@deepseek-ai/dsh-client-*` 包；需要控件就抄宿主样式，颜色只走 `--dsw-alias-*` token。
- 不要在组件外写 DOM、不要 iframe、不要把整个应用根替换掉。
- slot 组件抛错会清空该 slot（console: `slot entry crashed`），新代码先做空态保护。
- 主题 token 目前只有 14 个（`--dsw-alias-bg-base`、`bg-layer-1/2`、`bg-overlay`、`border-l1/l2`、`brand-primary`、`label-primary/secondary`、`state-error/idle/success/warn-primary`、`--dsw-specific-sidebar-fill`），纸色等装饰色可用固定色（artwork 例外）。

### 6.3 Host 半（Node）

- 形态：`export const name` / `export const inject = ["tools", "connection", "storageDomain", "webServer"]` / `export function apply(ctx, config)`。
- 资源注册用 `ctx.effect(...)` 或 `ctx.on(...)`，返回清理函数（domain 的 `close()` 必须挂在 effect 里，否则 reload 后 `already-open`）。
- 路由两条已验证写法：
  - `ctx.webServer.register(...)`（stock-assistant 用法）；
  - `ctx.connection.fetch.register(...)` + `ctx.on("webserver/index-inject", table => table.push({ kind:"global", name:"__CONFIG__", value:{routePath} }))`（sticky-notes 用法，推荐，能吃到宿主鉴权围栏）。
- 持久化两条已验证写法：
  - **单 JSON 文件**：`$DSH_HOME/sticky-board/board.json`，`tmp+rename` 原子写，`storePath` 可配置（sticky-wall 用法）；
  - **storageDomain**：`defineDomain({ name, version, tables: { notes: domainTable(schema) } })` + `ctx.storageDomain.open(spec)`，record 级读写、版本与 schema 校验（sticky-notes 用法）。
- 工具：`ctx.tools.register({ name, description, parameters, execute })`；工具与 HTTP 路由调用同一个 repository。
- 页面注入：把 routePath 写进页面（`webserver/index-inject`），Client 不硬编码路径。
- Host 半改动必须重启/关开插件才加载；Client 半刷新页面即可。

### 6.4 验证手段

- 安装结果看 `application` / `warnings`，不看日志。
- `cordis_inspect_query`（Client `Slots.listSubTree`）确认 `sidebar.panellist` 与 `main` 里出现新注册。
- 页面刷新后点左栏图标 → 面板出现；明暗主题各看一遍；console 无 slot 崩溃。
- 数据层：新建 → 刷新 → 仍在；重启 Harness → 仍在；模型工具写入后在 UI 可见（同一份数据）。
- 若浏览器控制不可用：只报「语法/清单/槽位注册已核验、视觉未核验」，不假称成功。

## 7. 推荐方案（路径 B：fork 便签墙底座 + 自建任务板）

### 7.1 为什么是这条

- `dsh-plugin-sticky-wall` 已把「便签墙」90% 的难点做完：自由摆放、拖拽/缩放、行级清单、折叠、纸色、回收站、搜索/整理、导入导出、5 个工具、原子写、同源校验、MIT 许可、零依赖。
- 任务板不需要重型库：列 + 卡 + 拖拽换列，用与墙相同的指针事件/HTML5 DnD 即可，保持「零构建、单文件 bundle」的部署优势。
- 数据同源后，**墙 ↔ 板联动**才是这个插件相对市场现有方案的真正差异点。

### 7.2 目录结构（建议）

```
sticky-board/
├── package.json            # @local/sticky-board, dsh.bundle.patch + dsh.client
├── cordis.patch.yml        # insert row: id=sticky-board
├── index.js                # Host：repository + 路由 + 工具 + 配置 + 页面注入
├── client.js               # Client：左栏入口 + main 面板（墙 / 板 / 详情抽屉）
├── locale/{zh,en}.json
├── icon.svg
├── lib/
│   ├── model.js            # 纯函数：normalize / sort / 过滤 / 墙↔板转换（可单测）
│   ├── store.js            # JSON 持久化：load / save 串行化 / revision / 损坏备份
│   ├── repository.js       # note / board / card 操作（UI 与工具共用）
│   ├── route.js            # /api/sticky-board/*
│   └── tools.js            # note_* / task_* 工具规格
└── test/                   # node --test：model / store / route / tools
```

### 7.3 数据模型（v1，单文档）

```jsonc
{
  "version": 1,
  "notes": [{
    "id": "note-…", "lines": [{ "id": "l1", "kind": "todo|text|ul|ol", "text": "…", "done": false }],
    "text": "派生可读副本（搜索/工具用）",
    "color": "amber", "pinned": false, "collapsed": false,
    "x": 0.12, "y": 0.2, "w": 260, "minLines": 4,      // x/y 存百分比，面板宽窄变化不散架
    "trashed": false, "deletedAt": null,
    "linkedCardId": null,                                // ← 联动
    "rev": 7, "createdAt": 0, "updatedAt": 0
  }],
  "boards": [{
    "id": "board-main", "title": "默认看板",
    "columns": [{ "id": "todo", "title": "待办", "order": 0 }, { "id": "doing", "title": "进行中", "order": 1 }, { "id": "done", "title": "完成", "order": 2 }],
    "cards": [{
      "id": "card-…", "title": "…", "note": "Markdown",
      "columnId": "todo", "order": 3,
      "priority": "P1", "labels": ["功能"], "dueDate": "2026-11-20",
      "done": false, "noteId": null,                     // ← 联动
      "createdAt": 0, "updatedAt": 0, "rev": 1
    }]
  }],
  "settings": { "activeView": "wall", "wallDensity": "auto" }
}
```

联动规则（v0.1）：
- `card.noteId` ↔ `note.linkedCardId` 双向引用；
- 「便签 → 任务」：便签标题/首行作卡标题，正文作卡描述，勾选行转为卡内子任务清单；便签保留并标记关联；
- 「任务 → 便签」：把卡标题+描述生成一张墙上的便签；
- 删除任一侧时只解链，不级联删除（回收站各自独立）。

### 7.4 持久化

- `$DSH_HOME/sticky-board/board.json`（默认），`config.storePath` 可改；
- 写入：临时文件 + `rename` 原子替换、内容未变跳过、写串行化、按文档 `rev` 做并发保护（本地改动计数，回包 rev 未变才清 dirty）；
- 损坏：启动解析失败 → 原文件改名 `.corrupt-<时间戳>` 备份并重建空文档，面板提示路径；
- 容量：建议上限 500 张便签 / 500 张卡；超过 ~1000 条或需要多端时再评估迁 `storageDomain` 或 SQLite；
- 导出/导入：整份 JSON（含回收站），`merge` / `replace` 两种语义。

### 7.5 HTTP 接口（Host 路由，同源 + 鉴权）

| 方法/路径 | 作用 |
|---|---|
| `GET /api/sticky-board/snapshot?trash=0` | 墙 + 板 + 计数（`trash` 明细按需拉） |
| `POST /api/sticky-board/note/upsert` | 新建/更新便签（`light` 回包只回 ack） |
| `POST /api/sticky-board/note/remove|restore|purge` | 回收站三件套 |
| `POST /api/sticky-board/card/upsert|remove|restore` | 卡片增改/软删/恢复 |
| `POST /api/sticky-board/card/move` | 跨列 + 列内排序（`columnId` + `toIndex`） |
| `POST /api/sticky-board/column/upsert|delete` | 列管理 |
| `GET/POST /api/sticky-board/export|import` | 备份/迁移 |

### 7.6 模型工具（8 个，与 UI 共用 repository）

`note_list` / `note_create` / `note_update` / `note_remove` / `board_get` / `task_create` / `task_update` / `task_move`（可选 `task_remove`、`note_restore` 共 10 个）。
参数语义与 UI 操作一一对应；工具返回文本 + 短 id，便于后续调用。若嫌工具多，可合并为单个 `sticky_board` 工具 + `action` 枚举（参考 `todo_time_log`）。

### 7.7 UI 结构（main 面板）

```
┌ 工具条：便签墙 | 任务板 | ＋新建便签 | ＋新建任务 | 搜索 | 筛选 | 回收站 | 设置 ┐
├ 墙视图：自由摆放（拖拽/缩放/折叠/纸色/置顶/横线纸/整理）                       │
├ 板视图：列（可增删改） + 卡片（拖拽换列、优先级色条、标签、截止、关联便签角标）   │
├ 右侧抽屉：任务详情 / 便签详情（编辑、关联、删除、恢复）                          │
└ 状态条：已保存 HH:MM · 数据路径（可复制）                                        ┘
```

- 主题：容器/控件全走 `--dsw-alias-*`；纸色为固定装饰色；
- 窄屏：墙面自动改为单列/磁贴；
- 交互：双击空白新建、`Ctrl/Cmd+N` 新建、`Ctrl/Cmd+F` 搜索、`Esc` 关抽屉/取消编辑（在输入框内时 Esc 优先给输入框）。

### 7.8 里程碑（AI 辅助，按实际连续投入估算）

| 阶段 | 内容 | 产出/验收 | 估时 |
|---|---|---|---|
| M0 | 骨架：package/patch/icon/locale、Host 空 apply、Client 左栏入口 + main 空面板，安装成功 | `install_bundle` → applied；左栏出现图标，点开有面板 | 0.5 天 |
| M1 | 便签墙：数据模型 + JSON 持久化 + snapshot/upsert/remove + 墙 UI（拖拽/缩放/颜色/置顶/回收站/搜索） | 新建/拖动/改色→刷新→重启仍在；工具可读 | 1.5 天 |
| M2 | 任务板：列/卡 CRUD + 拖拽换列/排序 + 优先级/标签/截止 + 详情抽屉 + 板/墙切换 | 关掉页面重开数据一致；回收站可用 | 1.5 天 |
| M3 | 联动 + 工具：便签↔任务互转、双向引用、8–10 个工具、筛选/搜索统一 | 工具创建的任务在 UI 可见；便签转任务可逆 | 1 天 |
| M4 | 打磨：导入导出、快捷键、明暗主题/空态/错误态、i18n、单测、验证记录 | `node --test` 通过；明暗主题截图；验证清单 | 0.5–1 天 |

合计约 **5–6 人日**（连续投入、AI 协作）；若只做「墙 + 三列板 + 基础联动」的 MVP，可压到 **2–3 天**。

### 7.9 风险与对策

| 风险 | 对策 |
|---|---|
| fork 上游 153KB 代码，改造成本/维护分叉 | 只 fork 需要的模块；把新增逻辑放 `lib/` 独立文件；保留 MIT 版权与 NOTICE；记录 upstream commit |
| 手写 client bundle 越写越大 | Client 侧按「墙/板/详情/工具条」拆函数；超过 ~200KB 或需要 dnd-kit 时再引入 esbuild 构建步骤 |
| Host/Client 半更新不同步 | 交付说明写清：Host 改完关开插件/重启，Client 改完刷新页面 |
| 左栏 order 冲突 | 安装前 `Slots.listSubTree('sidebar.panellist')` 查看；取 16/18 |
| 全量 JSON 写在数据量大时变慢 | 500/500 上限 + `light` 回包 + 内容未变跳过；超限迁 storageDomain/SQLite |
| 多窗口并发 | 轮询 snapshot（6s）+ `rev` 保护；不做实时协同 |
| DSH 版本升级 | 声明 `engines.dsh`；Client 只用 slots/locale/layout 等稳定面；避免依赖 Client 包 |

## 8. 备选路径对比

| 路径 | 做法 | 开发量 | 数据互通 | 风险 | 推荐度 |
|---|---|---|---|---|---|
| A. 直接装现成 | `dsh-plugin-sticky-wall` + `dsh-project-kanban`（或 `@alpacachen/dsh-kanban`）两个插件并用 | 0 | ❌ 两套数据、两套 UI | 低 | 先试用（1 小时） |
| **B. fork 便签墙 + 自建任务板** | 以 sticky-wall 为底座，加 board 模块与联动、工具 | 5–6 人日（MVP 2–3） | ✅ 同一文档 | 中 | **推荐** |
| C. 完全自研 | 只复用 DSH 机制与设计模式，从空 bundle 写起 | 7–10 人日 | ✅ | 中高 | 备选（想要代码完全自控） |
| D. 二开 `dsh-life-workbench` | 在已有工作台里加自由便签墙 | 3–4 人日 | ✅ | 中（其看板/数据模型较轻，需重做板） | 备选（若更看重仪表盘） |

> 建议：**先花 1 小时装 A 的两个插件实际点一遍**（尤其感受墙的拖拽手感与看板信息密度），再按 B 开工；这样「不重复造轮子」和「做出差异」两头都占到。
